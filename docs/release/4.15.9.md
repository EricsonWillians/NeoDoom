# BiasedDoom 4.15.9

BiasedDoom 4.15.9 is a scripting-toolchain release. The embedded Python
API gains a class registry with named constants and random spawns, dead
map triggers stop failing silently, and the whole write-test-debug loop
becomes scriptable: CI-grade test runs, machine-readable error feeds,
editor completions, and a console you can finally select and copy text
from.

## Python Scripting API

- `bd.actors` now doubles as an actor class registry: UPPER_SNAKE
  constants for every non-abstract actor class in the engine —
  `bd.actors.DOOM_IMP` is `"DoomImp"` — including classes defined by
  loaded mods, ZScript, DECORATE, and MAPINFO doomednums. The registry
  offers `names()`/`constants()`/`dir()` listing, `children_of()`
  ancestry queries, category helpers (`monsters()`, `projectiles()`,
  `weapons()`, `items()`, `players()`), `random(kind)` selection, and
  one-call `spawn_random(x, y, z, kind=...)` spawns. `bd.actors(...)`
  remains callable for live actor queries.
- New `line_activation_failed` event: when a line with a nonzero special
  is activated but the special fails (classically `ACS_Execute` with no
  backing script), the event reports the line, special, and arguments.
  Previously these triggers failed with no observable signal whatsoever.

## Testing and Tooling

- New `-scripttest <tics>` command-line mode: the level runs for the
  given number of tics, the engine prints `SCRIPT TEST: PASS/FAIL` with
  the Python error count, and exits 0, 1 (errors), or 2 (no level
  loaded). Map scripts are now CI-testable end to end.
- New `-pyerrorlog <file>` option appends every reported Python error as
  a JSON line (timestamp, map, context, repeat counts, traceback) for
  editors and automation. Heresy Editor surfaces this feed in its log
  window.
- New `dumppystub [path]` console command regenerates the actor-constant
  block of the `biaseddoom.pyi` type stub from the live class registry
  and warns about any public API missing from the stub.
- `docs/scripting/biaseddoom.pyi` is a full type stub of the embedded
  module — function signatures, `Actor`/`Line`/`Sector`/`Player` handle
  members, the actor registry, and all built-in actor class constants.
  Dropping it into a `typings/` folder at the VSCode workspace root
  enables completions and inline docs via Pylance's default stub path.

## Console Quality of Life

- The console scrollback supports mouse text selection: drag to
  highlight a range (across wrapped lines), Ctrl+C copies the selection,
  and Ctrl+A selects and copies everything with a visible highlight.
- New `copyconsole [N]` command copies the last N console lines (or the
  whole scrollback) to the OS clipboard with color codes stripped.
- Repeated identical Python errors are deduplicated with periodic
  "repeated N times" summaries instead of flooding the console at 35
  tracebacks per second, and buffered `print()` output is flushed before
  each traceback so messages and errors appear in the order they
  happened.

## Documentation and Website

- A static project website under `website/` (standard-library-only
  generator, restrained retro style) publishes guides, the events
  reference, the actor registry, console debugging, VSCode setup, and
  Heresy Editor integration. The API reference is generated from
  `biaseddoom.pyi`, so the website, the editor stub, and the engine can
  never drift apart. A GitHub Actions workflow deploys it to GitHub
  Pages.
- `docs/development/python-api-roadmap.md` is a critical analysis of the
  Python API and editor integration with prioritized proposals.
