Events

Scripts register callbacks with the @bd.on("name") decorator (or by defining a function named on_<name>). Every callback receives a single event dictionary.

The success rule (read this)

line_activated fires only when the line's special succeeds. A trigger whose special fails — classically ACS_Execute pointing at a script that doesn't exist — produces no event and no message. That silence has eaten entire afternoons.

line_activation_failed is the other half of the story: any line with a nonzero special whose execution fails raises it, with the special number and arguments included:

@bd.on("line_activation_failed")
def broken(event):
    bd.log(f"DEAD TRIGGER: line {event['line_index']} "
           f"special {event['special']} args {event['args']}",
           level="warning")
Tip: pair this with Heresy Editor's automatic BEHAVIOR stub generation and the failure event becomes something you only see when you actually broke something.

Filtering and scheduling

@bd.on("actor_died", class_name="DoomImp")   # only imps
def imp_down(event): ...

@bd.on("tick", every=35)                     # once per second
def heartbeat(event): ...

bd.schedule(my_task, delay=70, repeat=70)    # one-shot or repeating

Callback options: every (run every Nth occurrence), priority, class_name, tid, player. Whole-tic CPU budgets are enforced per callback; see bd.profile() in the API Reference.

Stale handles

actor_ref values are live handles. After the actor is destroyed or the level changes they become invalid: check .valid and expect ReferenceError from operations on stale handles. For persistence across savegames, keep TIDs in bd.state and re-resolve on load.
