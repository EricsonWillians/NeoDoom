The Actor Registry

bd.actors is two things at once: the classic snapshot query (bd.actors(class_name="ZombieMan")) and a registry of every actor class the engine knows — Doom, Heretic, Hexen, Strife and Chex classes, plus anything your mod defines in ZScript, DECORATE, or MAPINFO.

Constants instead of strings

bd.spawn_actor(bd.actors.DOOM_IMP, x, y, 0.0)     # "DoomImp"
bd.spawn_actor(bd.actors.MBF_HELPER_DOG, x, y, 0.0)  # "MBFHelperDog"

Constants are the UPPER_SNAKE rendering of the engine class name. Unknown attributes raise AttributeError with a pointer to the listing functions. The full constant table is at the bottom of the API Reference (1,558 entries on a stock Doom II setup).

Discovery

bd.actors.names()                 # every class name, sorted
bd.actors.constants()             # every CONST name, sorted
dir(bd.actors)                    # same, for interactive use
bd.actors.resolve("DOOM_IMP")     # "DoomImp"  (either form accepted)
bd.actors.children_of("Weapon")   # Weapon and all descendants
bd.actors.monsters()              # shootable, kill-counted actors
bd.actors.projectiles()           # missiles
bd.actors.weapons()               # Weapon descendants
bd.actors.items()                 # Inventory descendants
bd.actors.players()               # PlayerPawn descendants

Random selection and spawning

bd.actors.random()                  # any actor class
bd.actors.random("monsters")        # by category
bd.actors.random("DOOM_IMP")        # a class and its descendants

bd.actors.spawn_random(x, y, z)                       # random monster
bd.actors.spawn_random(x, y, z, kind="items")         # random pickup
bd.actors.spawn_random(x, y, z, kind="monsters",
                       angle=90.0, force=True)        # extra kwargs pass through

A wave spawner becomes three lines:

@bd.on("tick", every=70)
def wave(event):
    spot = SPAWNS[len(bd.actors()) % len(SPAWNS)]
    bd.actors.spawn_random(spot[0], spot[1], 0.0)

Editor completions

The registry is included in the biaseddoom.pyi type stub, so bd.actors. autocompletes every constant in VSCode. Mod-defined classes aren't in the static stub but resolve identically at runtime — the stub's __getattr__ keeps them type-check clean. See VSCode.

Keeping the stub current

The constant block in biaseddoom.pyi is generated from the live engine. With the game running:

dumppystub path/to/biaseddoom.pyi

refreshes the block in place (or writes a full skeleton when the file is missing) and warns if any public API is missing from the stub.
