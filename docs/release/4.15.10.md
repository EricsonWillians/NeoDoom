# BiasedDoom 4.15.10

BiasedDoom 4.15.10 is a glTF rendering overhaul. Models now render with
real PBR materials, translucency, correct facing, and correct node
transforms — real-world Blender/Sketchfab exports finally look the way
they were authored — and a batch of long-standing loader bugs (scrambled
multi-mesh geometry, precache crashes, flat-color fallbacks) is fixed.

## PBR Materials

- glTF materials render with the hardware PBR shader (GGX/Cook-Torrance
  specular): `metallicRoughnessTexture` channels are split and the
  `metallicFactor`/`roughnessFactor` values are baked in, normal maps
  and ambient occlusion maps (with `occlusionStrength`) bind as material
  layers, and emissive maps act as fullbright brightmaps. Factor-only
  materials get solid-value PBR layers, so a chrome bumper with
  `metallicFactor 1` / `roughnessFactor 0` picks up dynamic-light
  reflections. Non-PBR materials keep the standard Doom shading.
- `baseColorFactor` is now multiplied into the base color texture at
  render time instead of being ignored whenever a texture was present —
  near-black car paint no longer renders light gray.
- `alphaMode` is honored: `BLEND` meshes (car glass, baked
  shadow-catcher planes, stickers) render translucent in a second pass,
  and `MASK` meshes alpha-test at their material `alphaCutoff`.
- There is no environment map, so fully metallic surfaces still need
  dynamic lights to shine (same caveat as TEXTURES-defined PBR). Set
  `GLTF_NO_PBR=1` in the environment to force standard shading for
  comparison or troubleshooting.

## Correct Geometry, Facing, and Transforms

- **Breaking (visual)**: glTF models now face the actor's angle and are
  no longer mirrored (decal text reads correctly). The conversion swaps
  the X/Z axes with the same handedness as the MD3 path. Things placed
  in existing maps appear rotated 90°; add `AngleOffset -90` to their
  MODELDEF to restore the old look.
- Node transforms (TRS or `matrix`) are baked into the vertex data of
  unskinned meshes at load, so real-world assets with transformed nodes
  (most Sketchfab/Blender exports) render at the right size with all
  parts in place. Nodes authored with a `matrix` keep it raw instead of
  being lossily decomposed.
- Multi-mesh models no longer render scrambled: the vertex buffer stored
  globally-offset indices while the render state also shifted attribute
  pointers, so every mesh after the first read foreign vertices.
- Fixed a crash at level start with models having more than 32 meshes.

## Loading

- GLB files with embedded textures (bufferView, in-memory, and base64
  `data:` URIs) now load their textures instead of falling back to flat
  colors.
- Relative texture URIs resolve against the directory of the `.gltf`
  file itself (per the glTF spec), with a fallback to the historical
  flat `models/` prefix — models in subdirectories like
  `models/statue/statue.gltf` with sibling textures now work.

## Scripting

- `A_ChangeModel` no longer rejects an empty modeldef name: the ZScript
  `''` literal means "no override" and the actor's own MODELDEF is used.

## Known Issues

- glTF animation playback only applies to skinned meshes (armatures);
  plain node TRS animations on unskinned models render in bind pose.
- ZScript mixins do not cross compilation units, so `mixin GLTFModel`
  only works inside the engine pk3; mod ZScript should call the
  underlying `Actor` natives (`A_ChangeModel`, `GLTF_PlayAnimation`,
  `GLTF_UpdateModel`, ...) directly.
