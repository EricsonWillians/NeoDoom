# BiasedDoom 4.15.5

BiasedDoom 4.15.5 is a comprehensive procedural-generation and renderer
quality release. Generated missions now offer materially different layout,
verticality, detail, and outdoor-space choices; every theme has stronger
architectural authorship; progression gates receive explicit non-bypass
proofs; and the maximum supported map size has expanded from 20 to 80.

## Highlights

- Added deterministic **Layout Shape**, **Verticality**, **Architecture
  Detail**, and **Outdoor Spaces** controls to the Procedural Game menu. Each
  option changes validated map structure rather than acting as presentation-only
  metadata.
- Severely differentiated all five themes. Techbase, Hell, Industrial, Gothic,
  and Corrupted Tech now control silhouettes, ceiling and terrace behavior,
  courtyard cadence, interactive features, colored lighting, landmark
  materials, trim, texture phases, and prop rhythms.
- Expanded the map-size slider to 80. Very large maps reflow growth into both
  axes, center emitted coordinates, and guard UDMF limits instead of pushing
  the player start against the map boundary.
- Rebuilt vertical progression around broad `0 → 32 → 64 → 96` terraces and
  full-width 8-unit stair sectors. Required routes cannot become impassable
  ledges, while optional perches and lifts retain validated stair or bypass
  access.
- Made key-triggered ambushes and switch-opened opportunity caches more varied
  through alternate silhouettes, lighting, floor and ceiling treatments,
  reveal-door prominence, actor arrangements, and remote same-stage switches.
- Expanded IWAD-safe surface families, semantic accents, native-width door
  profiles, lintels, recessed approaches, secret rewards, survival caches, and
  role-aware decoration.
- Procedural savegames now archive the exact generated UDMF and its complete
  recipe, preserving the original map across generator revisions and avoiding
  invalid in-memory map-lump access during save/load.

## Progression and Topology Safety

Every composed connection is audited against its lock stage. A cross-stage
edge is accepted only when it is the planned keyed gate; normal doors, open
portals, loops, merged rooms, and remote switches cannot silently reconnect the
two sides. The structural validator also removes the keyed door sectors and
proves that no ordinary route can bypass the lock.

Maximum-size generation now rejects coincident solid lines, zero-area loops,
branched or open sector boundaries, synthetic hole subsectors, unsafe
decoration clearances, and untraversable height transitions before a map is
accepted. Same-room joins use explicit hall portals, and mandatory landmarks
have collision-checked fallbacks rather than blocking critical passages.

## Rendering and Screenshots

- Hardware sky fog now uses a non-overlapping 32-strip hemisphere with a true
  zenith pole and continuously interpolated opacity. Looking into the sky no
  longer exposes concentric rings or translucent triangle-fan wedges.
- GLES mapped-buffer subupdates no longer dereference a missing CPU shadow
  allocation when the sky-fog gradient is uploaded.
- Screenshot requests are captured after final 2D composition and before
  presentation on Vulkan, OpenGL, and GLES. Full-screen automap, HUD, and
  console layers are now included instead of capturing the hidden 3D frame.

## Release Validation

The release candidate passed `actionlint`, shell syntax checks, diff hygiene,
and a clean GCC 13 Release build of all 1,389 targets with glTF support enabled.
Release packaging also pins the POSIX MinGW-w64 thread model required by the
glTF dependency stack. The macOS artifact targets macOS 10.15 or newer so its
C++17 filesystem requirement matches both the binary and application metadata;
optional runtime resource directories are handled without aborting otherwise
complete native Windows or macOS packages.
The complete procedural regression matrix covered 15 substantive suites:

- seven representative structural configurations and eleven additional seed
  stress cases;
- sizes 1, 3, 5, 10, 20, 40, and 80;
- independent generation effects for all four new menu controls;
- five-theme texture, lighting, silhouette, and runtime differentiation;
- native 64/128-width and 72/96/112/128-height door profiles;
- staged secret rewards, difficulty balance, menu launching, and deterministic
  replay;
- Ultimate Doom roster and all-theme runtime compatibility;
- normal runtime loading from size 1 through size 80;
- an all-high size-80 map with 6,203 sectors and 7,991 things;
- fixed-seed size-80 structural and runtime validation for all five themes;
- five additional independent size-80 maps with developer-level BSP checks.

## Downloads

- Linux: download `BiasedDoom-4.15.5-Linux-x86_64.AppImage`, mark it executable
  if needed, and run it.
- Windows x64: extract `BiasedDoom-4.15.5-Windows-x64.zip` and run
  `biaseddoom.exe`.
- Windows x64 MinGW: extract
  `BiasedDoom-4.15.5-Windows-x64-MinGW.zip` for the Linux-built cross-compiled
  package.
- macOS 10.15 or newer: extract `BiasedDoom-4.15.5-macOS.tar.gz` and launch the
  application.
- Every artifact has a matching `.sha256` checksum file.
- A supported IWAD such as `DOOM2.WAD` is required and is not included.
