VSCode

The biaseddoom module exists only inside the running engine, so editors need a type stub. BiasedDoom ships one at docs/scripting/biaseddoom.pyi: every function signature, the Actor/Line/Sector/Player handles, the actor registry, and all built-in actor class constants.

Setup (zero configuration)

Pylance reads stubs from a typings/ folder at the workspace root by default. Open your sidecar as the workspace and drop the stub in:

mymap.scripts/
    typings/
        biaseddoom.pyi      <-- copy from docs/scripting/
    scripts/
        main.py

Reload the window if VSCode was already open. From then on import biaseddoom as bd completes everything, down to bd.actors.DOOM_IMP.

Heresy Editor users: the editor installs and refreshes this stub for you (Preferences → Scripting → install typings stub into script folders). Files you customize are never overwritten.

Keeping the stub in sync

The actor-constant block is engine-generated. After adding mod classes or updating the engine, refresh it from the running game:

dumppystub "path/to/typings/biaseddoom.pyi"

The command also warns when the stub is missing public API entries.

Attaching the debugger

Start the game with the DAP server enabled (Heresy does this via its -debug 19021 preference), then add this to .vscode/launch.json inside the scripts directory:

{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Attach to BiasedDoom",
            "type": "zscript",
            "request": "attach",
            "port": 19021
        }
    ]
}

The DAP server speaks the Debug Adapter Protocol for ZScript; Python scripts debug best through the console and the error feed.
